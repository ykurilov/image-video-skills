# Как писать промпты для Nano Banana 2.1 - исследование

Дата: 10 ноября 2026. Основа для скилла по написанию промптов.

## Пометки достоверности

- **[О]** - официальный материал Google (документация Gemini API / AI Studio, карточка модели DeepMind, страница модели, блоги и DevRel Google).
- **[П]** - эксперимент практика с описанной методикой (обычно 1 генерация на задачу - это не статистика).
- **[М]** - мнение, совет без теста, расхожее утверждение.
- **(старая версия)** - сведения про Nano Banana 2 / Pro, на 2.1 не проверены.

## Что это за модель

- Выпущена 6 октября 2026, сразу без «preview». ID в Gemini API: `gemini-nano-banana-2.1`. Основа - Gemini 3.6 Flash. Google называет её основной рабочей моделью и «более экономным напарником» Pro. [О] [документация](https://aistudio.google.com/docs/image-generation), [карточка модели](https://deepmind.google/models/model-cards/nano-banana-2-1/)
- Соседи по линейке [О]: Nano Banana 2 (`gemini-3.1-flash-image`, устарела), Nano Banana 2 Lite (`gemini-3.1-flash-lite-image`, без поиска, плохо держит много опорных картинок и правку в несколько ходов), Nano Banana Pro (`gemini-3-pro-image`, сложные инструкции, плотный текст, единственная со «стилевыми» опорными картинками).
- Знания модели - до марта 2026, в части областей до января 2025. [О] карточка модели
- Все картинки с невидимым водяным знаком SynthID. [О]

## 1. Как модель читает промпт

### Стиль текста
- **Связное описание, а не теги.** Google: «Stop typing keywords and start directing the scene», «A simple list of keywords won't cut it». [О] (старая версия - гайд для NB2/Pro) [Google Cloud](https://cloud.google.com/blog/products/ai-machine-learning/ultimate-prompting-guide-for-nano-banana), [гайд Google по Pro](https://dev.to/googleai/nano-banana-pro-prompting-guide-strategies-1h9n)
- Тест на 2.1: промпт полными предложениями воспроизвёл все заданные детали. Тот же смысл тегами через запятую дал чистое фото, но модель сама добавила предметы и потеряла одну деталь. Вывод автора: теги не ломают картинку, они отдают решения модели. [П] [Fuser](https://fuser.studio/articles/nano-banana-prompt-guide)
- **Начинать с глагола-задачи** (создай / измени / объедини). [О] (старая версия) Google Cloud. Близкий совет для 2.1 - «сначала назвать задачу, потом стиль». [М] [Astorie](https://astorie.ai/blog/nano-banana-2-1-prompt-guide)
- **Назначение картинки** («логотип для дорогой минималистичной косметики», «для бразильской кулинарной книги»). По нему модель сама выводит свет, подачу, глубину резкости. [О] документация, гайд по Pro
- **Конкретные материалы и предметы**: «тёмно-синий твид», а не «пиджак». [О] (старая версия) Google Cloud
- **Язык камеры работает**: тип плана, объектив, угол, глубина резкости, свет с его ролью («три софтбокса», «контровой свет золотого часа»). [О] Фокусное расстояние + указание на размытие держат кадр надёжнее, чем «крупный план», «профессиональный». [М] [Runware](https://runware.ai/docs/models/google-nano-banana-2-1/guides/prompting)

### Формулы Google
- Генерация: `[Объект] + [Действие] + [Место] + [Композиция] + [Стиль]`. [О] (старая версия) Google Cloud
- С опорными картинками: `[Опорные картинки] + [Как они связаны] + [Новая сцена]`. [О] (старая версия)
- С поиском: `[Что найти] + [Как применить данные] + [Как изобразить]`. [О] (старая версия)
- Шаблоны из документации 2.1: фото («A photorealistic [shot] of [subject] in [setting]. [Light]. Shot from [angle] with [lens]»), стикер, текст, товар, минимализм с пустым местом под текст, комикс, эскиз в фото, разворот персонажа. [О] [документация](https://aistudio.google.com/docs/image-generation)

### Порядок и длина
- Ограничения длины на практике нет (контекст 1М токенов [О]; у посредника Runware поле до 45 000 символов). Модель «следует длинным подробным промптам» [М] [OpenArt](https://openart.ai/blog/nano-banana-2-1-prompt-guide/).
- **Порядок важнее длины**: идти от объекта наружу - объект, одежда, обстановка, кадр, свет, камера. Те же факты одной сплошной фразой теряют детали. [М/П] Runware
- **Сложную сцену - по шагам** («сначала фон, затем объект, наконец деталь»). [О] документация (лучшие практики)
- **Счёт и места - жёстко**: «ровно три миски в ряд посередине». Слово «exactly / ровно» делает число обязательным. [П] Runware
- Описывать характерные особенности персонажа в начале промпта. [М]

### JSON и списки
- Официально Google про JSON ничего не говорит; все примеры Google - связный текст. [О]
- Контролируемых тестов, где JSON лучше, не найдено. Тест Chase Jarvis (Nano Banana Pro, 2 прогона): JSON ничего не «закрепил». [П] (старая версия) [Chase Jarvis](https://chasejarvis.com/blog/does-json-prompting-actually-work-tested-with-nano-banana/). Сторонники JSON - продавцы шаблонов, без методики. [М]
- Разумная польза JSON - держать одинаковые поля в серии картинок, а не качество. [М] [Virse](https://www.virse.ai/blog/nano-banana-2-1-prompt-guide)

### Язык промпта
- Google: модель лучше всего работает на 15 языках, **русский (ru-RU) в списке**, украинский тоже. [О] документация, раздел ограничений
- Честного сравнения «один промпт на русском и английском» для 2.1 не найдено. Тест на 14 русских промптах: 2.1 поняла всё, текст написала по-русски без перевода. [П] [Хабр, SYNTX](https://habr.com/ru/companies/syntx_ai/articles/1093216/), [vc.ru](https://vc.ru/ai/3194928-nano-banana-2-1-i-pro-perevodyat-tekst)
- «На английском на 30-50% точнее» - ничем не подтверждено. [М] Совет «если русский не сработал - переведи и повтори» и «английский стабильнее для камеры, света, материалов» - мнение практиков. [М]
- Можно писать промпт на одном языке, а текст на картинке просить на другом. [О] (старая версия) Google Cloud

## 2. Сильные стороны и провалы

### Сильные (по бенчмаркам Google - самоотчёт, независимой проверки нет)
Elo «2.1 с размышлением / без / NB2 / Pro» [О] карточка модели, [The Decoder](https://the-decoder.com/googles-new-image-model-nano-banana-2-1-generates-better-images-for-less-money/):
- общее предпочтение 1050 / 1015 / 990 / 935;
- инфографика: дизайн 1048 / 1001 / 961 / 912, фактическая точность 0.521 / 0.328 / 0.179 / 0.265;
- правка по маске/рисунку 1049 / 1042 / 965 / 927;
- несколько персонажей 1106 / 1068 / 978 / 1011; товар 1024 / 981 / 955 / 965; несколько опорных 1066 / 1041 / 988 / 989.
- Отдельно Google выделяет: вёрстку (постеры, швейцарский стиль, макеты сайтов), сохранение объекта при смене окружения, макросъёмку, живописные стили. Исправлены повторяющиеся куски («плитка») на очень широких кадрах. [О] [страница модели](https://deepmind.google/models/gemini-image/flash/)

### Провалы - официально признанные [О] карточка модели
- Мелкий текст размыт (особенно в 1K), длинные абзацы и «страница текста» - плохо.
- Персонаж не всегда совпадает с опорной картинкой.
- При правке по маске/рисунку инструкция выполняется частично, нарисованные пометки остаются на картинке.
- Иногда при правке сохраняется поза исходника, даже если просили другую.
- Путает лево/право.
- Ограничена в трёхмерном мышлении, фактах о мире.
- Google DeepMind: «can still struggle with small faces, accurate spelling, and fine details». [О] через [Fello AI](https://felloai.com/nano-banana-2-1/)

### Провалы - практики
- Масштаб: лошадь вышла пони; по сравнению с Pro менее натуральные цвета и пропорции. Pro всё ещё часто красивее. [П] The Decoder
- «Слева от робота» поняла как слева от зрителя. Решение - писать «в левой части кадра (слева от зрителя)». [П] [DataCamp](https://www.datacamp.com/blog/nano-banana-2-1)
- Кадрирование: просили «по грудь» - вышло по пояс. [П] Fuser
- Часовая стрелка на 7, а не между 7 и 8; заголовок сам ушёл в капс; длинное тире вместо среднего; пропала запятая и двоеточие; добавлен непрошеный подзаголовок. [П] Хабр, SYNTX
- Жалобы на Reddit: «игнорирует инструкции», «не любит пустое место» - дорисовывает мебель и фон. Разбор: 2.1 по умолчанию «думает» (уровень medium) и свободнее толкует расплывчатый промпт, чем NB2, которая рисовала буквально. Лечение: прямо писать «больше ничего нет», «нижняя треть пустая». Эти фразы оказались важнее уровня размышления. [П/М] [Atlas Cloud](https://www.atlascloud.ai/blog/tips/nano-banana-2.1-whats-new)
- При этом другой тест: 2.1 точнее держит дословный текст меню, чем NB2 (та добавила нумерацию). [П] [DEV](https://dev.to/lee_315dd1e13420e63e2b813/nano-banana-21-vs-nano-banana-2-same-prompts-side-by-side-and-what-to-change-in-your-code-ik4)

## 3. Текст на картинке, вёрстка, инфографика, интерфейсы

- **Точный текст - в кавычках**, плюс шрифт или его описание, место и размер («жирный заголовок сверху», «цены выровнены вправо»). [О] Шаблон Google: `Create a [image type] for [brand] with the text "[text]" in a [font style]...`. [О] документация
- **Сначала текст, потом картинка**: лучше сперва согласовать текст (в чате с моделью или заранее), затем просить картинку с ним. [О] документация, раздел ограничений
- **Текст коротким**: заголовок, цена, несколько подписей. [О] карточка + [М] OpenArt
- **Регистр писать так, как нужно** - заглавными там, где нужны заглавные. [М] Atlas Cloud. Учесть: 2.1 сама может перевести заголовок в капс. [П] SYNTX
- Разное оформление для каждой строки работает: «верхняя строка - кистевой шрифт, средняя - тяжёлый блочный, нижняя - тонкий». [О] (старая версия)
- **Кириллица**: в независимых тестах 2.1 писала русский текст без опечаток, включая «ё», №, ₽, среднее тире в «19:00–21:30». Ошибки - в мелочах: знаки, регистр, лишние подписи. [П] [Хабр](https://habr.com/ru/companies/syntx_ai/articles/1093216/), [vc.ru](https://vc.ru/ai/3194928-nano-banana-2-1-i-pro-perevodyat-tekst), [Хабр, 3 промпта](https://habr.com/ru/companies/syntx_ai/articles/1091964/). Надпись на мелком шевроне не прочиталась ни у 2.1, ни у NB2. [П]
- По русскому тексту 2.1, NB2, Pro и GPT Image 2.5 примерно равны; для идеально точного русского текста авторы теста советуют Pro или GPT Image, у 2.1 проверять регистр и знаки. [П] SYNTX
- **«Другого текста нет» не гарантирует** отсутствие лишних надписей (строка статуса телефона, шкалы, подписи). Проверять глазами. [П] SYNTX, vc.ru
- Чтобы не было случайного текста, описывать чистый фон. [М] Fuser
- Вывески внутри фотосцены у 2.1 хуже, чем у GPT Image 2.5. [П] Fuser
- **Инфографика**: главный рост 2.1. Тест: NB2 оставила недорисованную схему, 2.1 - полная: заголовок, 4 этапа, стрелки, без лишнего текста. [П] DataCamp. Для плотной инфографики и постеров - уровень размышления `high`. [М/П] Atlas Cloud, Runware
- Можно попросить «сжать» длинный текст или PDF в наглядную схему, задать вид: «редакционная вёрстка», «технический чертёж», «рисунок маркером на доске». [О] (старая версия, Pro)
- **Интерфейсы**: макеты сайтов - заявленная сильная сторона 2.1 [О]. Каркас (wireframe) или эскиз как опорная картинка жёстко задают вёрстку. [О] (старая версия, Pro)
- Пустое место под текст: «один объект в [месте кадра] на огромном пустом [цвет] фоне». [О] шаблон документации
- Для печати мелкого текста - 2K/4K, в 1K мелкий текст размыт. [О] карточка

## 4. Опорные картинки и правка

### Сколько и как
- До **14** опорных картинок: до **10 предметов** с высокой точностью и до **4 персонажей**. Стилевые опорные картинки у 2.1 **не поддерживаются** (у Pro - до 3). [О] документация. На странице DeepMind упомянуто «до 5 персонажей» - похоже, про NB2; доверять документации API (4). [О, расхождение]
- Можно дать видео (YouTube или файл) как источник. [О]
- Опорные картинки оплачиваются как входные токены, вход у 2.1 втрое дороже NB2. [О/П] [Apidog](https://apidog.com/blog/nano-banana-2-1-api/)
- **Ссылаться по порядку**: «логотип со второй картинки», «первая картинка - женщина». [О] пример документации
- **Каждой картинке - роль**: «картинка 1 - женщина, 2 - куртка, 3 - комната». [М] OpenArt, Astorie. Ограничивать роль: «картинка 2 - только цвета и дневной свет комнаты, предметы с неё не переносить». [М] [PromptZone](https://www.promptzone.com/drewgrant/nano-banana-21-prompts-real-examples-and-model-guide-4k4p)
- Чистые, хорошо освещённые фото; товар - с нескольких сторон, если важна этикетка. [М] OpenArt
- В группе персонажей - разная одежда, чтобы внешность не перетекала. [М]

### Сохранить лицо, персонажа, товар
- Прямо и подробно описать то, что должно остаться: «черты лица точно как на картинке 1», «форма, этикетка и крышка без изменений». Google: описывать ключевые детали (лицо, логотип) подробно и требовать, чтобы они «remain completely unchanged». [О] документация, гайд по Pro
- Перечислять конкретно, что сохраняется, лучше, чем общее «всё остальное то же». [П/М] Fuser
- Разворот персонажа: один ракурс за раз, предыдущие результаты добавлять в следующий запрос; для сложной позы - опорная картинка позы. [О] документация
- В серии повторять неизменные детали в каждом промпте (цвет этикетки, место логотипа, лицо, одежда). [М] OpenArt
- Цвет глаз называть точно в каждом промпте, держать одинаковый ракурс камеры. [М]
- Тест: при переносе сцены в новое место 2.1 сохранила объекты «до позы», но добавила роботу антенну. [П] DataCamp

### Изменить одно, не трогая остальное
- Шаблон Google: «Using the provided image, change only the [element] to [new]. Keep everything else in the image exactly the same, preserving the original style, lighting, and composition». [О] документация
- Отдельной загрузки маски нет: область задаётся словами («семантическая маска»). [О/П] Apidog, Fello AI
- Можно обвести область ярким цветом прямо на картинке и сослаться на пометку: «внутри области, обведённой красным, добавь...; красную обводку убери; всё вне её без изменений». [М] [Picsart](https://picsart.com/blog/nano-banana-2-1-picsart-integration/). Официально: пометки могут остаться и инструкция выполниться частично - просить убрать пометку и проверять. [О] карточка
- Одна правка за ход. [О] (лучшие практики «iterate») + [М] OpenArt
- Расплывчатое «сделай диван красивее» может перерисовать всю сцену. [М] Apidog
- «Если картинка верна на 80% - не генерировать заново, а править». [О] (старая версия, Pro)
- Тест: «измени только цвет лейки на красный» - 2.1 сохранила остальное, NB2 добавила царапины. [П] DataCamp. Замена камня на дерево - изменился только блок. [П] Fuser

### Правка в несколько ходов
- Разговор - рекомендованный Google способ доводить картинку: в API передаётся `previous_interaction_id`, в новом сообщении - только изменение. Пример Google: «Update this infographic to be in Spanish. Do not change any other elements of the image.» [О] документация
- После ~5 ходов детали плывут: руки, пальцы, цвет глаз. Советы: повторять список того, что сохраняется, заново прикладывать исходную опорную картинку, начинать новую сессию раз в ~5 ходов. [М] (частично наблюдения на NB2) [обзор](https://toolstofind.com/blog/google-nano-banana-2-1-guide), [note.com](https://note.com/suthio/n/n6033e6163722?hl=en). Цифры «2.1 держит 6 ходов, Pro - 8» ненадёжны.

## 5. Размышление и поиск

### Размышление
- Всегда включено, в API **выключить нельзя**. Модель делает до двух промежуточных картинок, итог - последняя. [О] документация
- Уровень `thinking_level`: `minimal`, `medium` (**по умолчанию**), `high`. У NB2 были только `minimal`/`high`, по умолчанию `minimal`. [О]
- Тест: 7 видов инструментов, заданное число и 3 ряда. `minimal` ошибся в счёте, `medium` посчитал верно, только `high` разложил по трём рядам. Совет: оставаться на умолчании, переходить на `high`, когда модель ошибается в счёте или расположении. [П] Runware
- Тест меню на всех трёх уровнях: текст, число строк, пустое место выполнены везде; отличалась только вёрстка. Время 15-40 с на любом уровне. [П] Atlas Cloud
- На уровне medium 550-1383 токенов размышления на картинку, 2.1 медленнее NB2 (25 с против 15, 34 с против 22). [П] DEV
- Для промпта: уровень задаётся параметром, писать «подумай» в тексте бессмысленно [М, вывод]. Логичный порядок шагов в промпте помогает модели рассуждать. [М]
- В бенчмарках Google режим с размышлением лучше во всём, сильнее всего - в фактах инфографики (0.521 против 0.328). [О]

### Поиск
- Веб-поиск: инструмент `google_search`. Поиск картинок (только 2.1 и NB2): `search_types: ["web_search","image_search"]`. [О] документация
- Когда нужен: свежие данные (погода, счёт матча, новости), реальные места, точные виды животных, реальные товары. Для вымысла и абстракции - не нужен. [О] + [М]
- Формулировка: назвать конкретный реальный объект и прямо попросить точности: «архитектурные детали, шпиль, площадь и горы - как в реальности». [О] (старая версия) [гайд Google по NB2](https://dev.to/googleai/getting-the-most-out-of-nano-banana-2-502k)
- Пример Google: «Make a simple but stylish graphic of last night's Arsenal game in the Champion's League». [О]
- **Людей по поиску картинок модель не использует.** [О]
- Поиск путает и смешивает сведения - проверять факты. [О] (старая версия, Pro) Не просить поиск придумывать цифры. [М]
- При показе результатов с поиском картинок пользователю обязательно показывать `search_suggestions`. [О]

## 6. Параметры запроса - не писать их в промпт

- **Соотношение сторон** `aspect_ratio`: 1:1, 1:4, 1:8, 2:3, 3:2, 3:4, 4:1, 4:3, 4:5, 5:4, 8:1, 9:16, 16:9, 21:9. [О]
- **Размер** `image_size`: `1K` (по умолчанию), `2K`, `4K`, буква K только заглавная. 512px у 2.1 нет. [О]
- Без параметра: размер как у входной картинки, без входной - квадрат 1:1. [О]
- Формат ответа: только картинка или картинка + текст (`response_format`). В AI Studio / Interactions API это `response_format`, у Vertex и посредников - `image_config`. [О/П]
- **Уровень размышления, поиск** - тоже параметры, не текст. [О]
- На Vertex AI не поддерживаются seed, temperature, topK, topP - вызывают ошибку. [П] Fello AI. Значит, повторяемость только через текст и опорные картинки.
- Число картинок модель может выдать не точно то, что просили. [О]
- Писать «16:9» в тексте - Google сам так делает в примерах дополнительно к параметру; вреда нет, но решает параметр. Для широких полос (4:1) описывать сцену с центром и чем-то по бокам, чтобы заполнить ширину. [О] + [М] Runware
- «4K» в тексте вместо параметра - бессмысленно. [вывод из О]
- Мелочь для скилла: у посредников (fal, Kie, OpenRouter, Higgsfield) названия параметров свои, часть настроек может быть не выведена. [П]

## 7. Отрицания

- Google: «семантические негативные промпты» - описывать желаемое, а не запрет. Вместо «без машин» - «пустая безлюдная улица без следов транспорта». [О] документация, Google Cloud
- Поля для негативного промпта нет. [О]
- Но короткие запреты в конце работают на практике: «Negative prompt: people, crowds, tourists» убрал людей с моста [П] Runware; «больше ничего нет», «нижняя треть пустая» решили проблему дорисовок у 2.1 [П] Atlas Cloud. Гарантии нет: «другого текста нет» не всегда спасает от лишних надписей [П] SYNTX.
- Google сам пишет запреты в примерах («Do not change any other elements», «ONLY inside the letterforms» заглавными для акцента). [О]
- Итог для скилла: главное - описать нужное состояние; короткое явное ограничение - как подстраховка. [вывод]

## 8. Что не работает или вредит по сравнению со старыми привычками

- Теги через запятую («dog, park, 4k, realistic», «8k, masterpiece») - Google прямо называет это плохим примером («tag soup»). [О] (старая версия, Pro). На 2.1: теги отдают решения модели. [П] Fuser. Слова качества ничего не добавляют. [М]
- Веса вида `(word:1.3)`, скобки - Google нигде не упоминает, синтаксиса нет. Тестов на 2.1 не найдено. [не найдено]
- Отдельного негативного промпта нет. [О]
- Seed и temperature для повторяемости недоступны. [П]
- Промпты, отлаженные под буквальную NB2, на 2.1 могут толковаться свободнее - добавить явные ограничения или поставить `minimal`. [М/П] Atlas Cloud
- Совет Google для NB2 «размышление по умолчанию выключено, включать только для сложного» ([гайд NB2](https://dev.to/googleai/getting-the-most-out-of-nano-banana-2-502k)) к 2.1 не относится: тут по умолчанию medium. [О]

## 9. Отличия от прошлых версий

| | NB (2.5 Flash) | NB2 | Pro | **2.1** |
|---|---|---|---|---|
| Размышление | нет | minimal/high, умолч. minimal | всегда | minimal/medium/high, умолч. medium |
| Размеры | ~1K | 512, 1K, 2K, 4K | 1K-4K | 1K, 2K, 4K |
| Крайние форматы 1:8...8:1 | нет | да | нет | да, без «плитки» |
| Персонажи / предметы | ~3 картинки | 4 / 10 | 5 / 6 (+3 стиля) | 4 / 10, стиля нет |
| Поиск картинок | нет | да | только веб | да |
| Кириллица на картинке | нет [П] | да | да | да |

[О] документация; кириллица у NB1 - [П] Хабр.
- Больше всего выросли: инфографика, несколько персонажей, правка по маске. [О]
- Цена картинки вдвое ниже NB2, но вход и размышление дороже. [О/П]
- Pro всё ещё рекомендуют для самых сложных профессиональных задач и плотного текста. [О] + [П] The Decoder

## Где сведения ненадёжны

- Все цифры качества - самоотчёт Google. Независимых тестов немного, по 1 генерации на задачу.
- Русские тесты (SYNTX, Study AI, Bratuha) - от компаний, продающих доступ.
- Официального поста Google с советами именно по 2.1 не найдено. Многие советы Google - из гайдов по NB2 и Pro (помечены).
- Расхождения: 4 или 5 персонажей; дата отключения NB2 (29 октября - отменено, даты нет); цена 4K менялась.
- JSON, веса, «masterpiece» на 2.1 никто строго не проверял.
- Сравнение русского и английского промпта на 2.1 не найдено.
- Как именно передавать маску-картинку в API - официально не описано; только словами или пометкой на самой картинке.
- Число ходов до «расползания» правок - только мнения.
